# CloudPath Analyzer — 1차 출시 범위 및 완료 기준

- 작성일: 2026-11-25
- 상태: 1차 개발 범위 개정안 (기능 구현 완료 선언이 아님)
- 적용 기준: Phase 6-1-4 이후 개발 계획
- 상위 비전: 기존 PROJECT_VISION.md의 범용·하이브리드 인프라 분석 목표를 유지한다.
- 범위 우선순위: 이 문서는 1차 출시 범위와 완료 판정에 한해 기존 로드맵을 보완한다. 기존 설계의 기술적 원칙이나 장기 목표를 폐기하지 않는다.

## 1. 목표

AWS 인프라를 배포 전과 배포 후 모두 분석하고, 구조·정책·예상 전달 경로 및 장애 원인을 웹에서 안정적으로 확인할 수 있는 독립적인 분석 서비스를 1차 출시(V1)의 목표로 한다. IaC 검증과 실제 구성 분석은 동일한 공통 데이터 모델을 사용하되 입력의 출처 및 확실성을 구분한다. 시각적 편집은 1차 출시의 필수 기능이다. 일정이나 테스트 개수만으로 완료를 선언하지 않는다.

## 2. AWS 인프라 종합 분석의 범위

‘AWS 전체 분석’은 모든 AWS 서비스와 기능을 무조건 지원한다는 의미가 아니다. 지원 범위를 명시한 AWS 네트워크 중심 종합 분석을 의미하며, 아래의 V1 필수 범위 및 종단 간 시나리오를 검증해야 한다. 개별 서비스에서 미지원 속성이나 연결은 UNKNOWN 또는 지원 범위 외로 표시한다. 전체 서비스 카탈로그에 대한 완전한 지원은 장기 확장 과제로 남긴다.

| 영역 | V1 필수 개발 목표 (완료 여부와 별개) |
|---|---|
| 입력 | 복수 Terraform HCL, Plan JSON, AWS 읽기 전용 Inventory. 변수·Module·반복 생성 및 미확정 관계에 대한 명시적 처리 |
| 기본 네트워크 | VPC, Subnet, EC2, ENI, SG, NACL, Route Table, IGW, NAT Gateway; 기본/명시적 연결, 경로 우선순위, blackhole, NAT 변환 |
| 연결 확장 | VPC Peering, Transit Gateway, VPC Endpoint(Interface/Gateway), 다중 VPC 경로. 계정·Region 경계 및 수집 누락을 명시 |
| 서비스 경로 | ALB/NLB Listener·Target Group, ECS/Fargate, RDS, EKS의 VPC/노드/ENI 수준 연결, S3 접근 경로. EKS Pod 내부 및 서비스 메시 등은 별도 지원 명세 필요 |
| 접근 제어 | 네트워크 정책과 IAM/리소스 정책을 분리. 지원되는 API 접근 조건과 관련 정책을 평가하고 미지원 조건·SCP·세션 정책 등 확인 불가 영역은 UNKNOWN |
| 진단 | 요청/응답, 최초 차단, 후속 조건부 차단, 자연어 규칙 근거, 구조도 강조 및 원본 증거 |
| AWS 도구 연계 | Reachability Analyzer 결과(정적 검증)와 Flow Logs(관측) 가져오기 및 비교. 별도 명시적 동의 없이 유료 분석 실행 또는 리소스 변경 금지 |

IPv4를 우선 검증하되 IPv6, 다중 계정/Region, 복합 하이브리드 연결은 실제 지원 수준을 별도 매트릭스에 기록한다. 미검증 경로를 지원 완료로 주장하지 않는다. DNS, TLS, OS 방화벽, 애플리케이션 동작 등은 별도 증거 없이는 통신 성공으로 확정하지 않는다.

## 3. 웹 시각화 및 구조도 편집 요구사항

- Network Topology: VPC/Subnet 소속 경계, 정책 적용 관계, 경로 대상, Packet Trace 강조를 구분한다. IaC References는 코드 의존성을 표현한다.
- 편집 모드: 리소스 박스 드래그, 소속 영역 내부 이동, 경계 밖 정책의 배치 제약, 연결선 재계산 및 장애물 회피를 제공한다. 이동은 시각적 좌표만 변경하며 실제 리소스의 소속·정책·분석 결과를 변경하지 않는다.
- 접기/펼치기: VPC/Subnet 단위로 내부 노드를 요약한다. 접힌 그룹의 외부 연결은 요약하고 내부 차단/미확정 개수 및 상태를 표시한다. 원래 경로의 의미나 차단 지점을 숨기지 않는다. 접기/펼치기에 따라 분석 결과가 바뀌지 않는다.
- 배치 저장: 입력 지문 및 그래프 모드별로 사용자 배치를 저장·복원하고 자동 배치로 초기화할 수 있어야 한다. 입력 변경 시 삭제된 리소스나 잘못된 소속의 좌표를 재사용하지 않는다. 초기 구현은 로컬/브라우저 저장을 기본으로 하고 민감한 구성 자체는 불필요하게 저장하지 않는다.
- 가독성: 확대/축소, 이동, 빈 영역 제거, 정책 계층 토글, 확대율과 독립적인 리소스 팝업, 차단 진단 팝업 및 상세 원본 JSON을 유지한다.
- 성능: 대형 입력에서 브라우저가 멈추지 않도록 제한·취소·오류 표시 또는 단계적 렌더링을 제공한다. 표시하지 못한 선 또는 겹침을 숨기지 않는다.

## 4. 판정 정확성 원칙

- 공통 모델에서 소속, 정책 적용, 전달, IaC 의존성을 분리한다. Forwarding과 Policy Evaluation을 분리하고 요청/응답을 평가한다.
- HCL/Plan 예상 판정, AWS 수집 구성의 정적 판정, Reachability Analyzer의 정적 결과, Flow Logs의 실제 관측을 구별한다. 수집 시각·범위·제약 및 입력 지문을 표시한다.
- 확정되지 않은 ID, 다중 후보, 누락된 규칙, 지원하지 않는 기능은 임의의 연결이나 PASS로 변환하지 않는다. 조건부 후속 결과는 최초 차단의 실제 도달 여부와 구별한다.
- AWS 설정이 허용하는 경로와 실제 애플리케이션 응답은 동일하지 않다. 분석은 읽기 전용이며 자동으로 배포하거나 정책을 수정하지 않는다.

## 5. 안정적인 웹 서비스 제공

- 설치/기동/재기동/분석/초기화 절차 및 오류 복구 문서화. 입력 검증, 일관된 오류 응답, 분석 시간 제한, 요청 제한, 실패 시 이전 정상 구성 보존, 동시 요청 및 오래된 입력 지문 처리.
- 데이터 및 자격증명 보호: AWS 인증은 수집 경로에만 사용, 최소 조회 권한, 입력/로그/결과의 민감 정보 최소화, 비밀값 저장·공개 금지, 파일 크기 및 구조 제한, 안전한 출력 인코딩.
- 기본 V1 운영은 단일 사용자 로컬/신뢰된 환경으로 제안한다. 외부 또는 다중 사용자 공개가 목표라면 인증·인가, TLS, 세션/테넌트 격리, 비밀 관리, 운영 모니터링, 보관/삭제 정책을 출시 필수 조건으로 추가한다. 개발용 로컬 서버를 그대로 공개하지 않는다.
- 상태 확인, 재현 가능한 테스트, 설치/실행 가이드, 버전 및 지원 범위 문서를 제공한다. 운영 환경, 부하 규모, 응답시간 목표는 별도 측정 후 확정한다.

## 7. V1 완료 판정 (Definition of Done)

다음 항목을 모두 충족하고 증거를 기록해야 한다.

- [ ] 지원 서비스/속성/경로 매트릭스 작성 및 필수 범위 구현·검수. 미지원 범위는 명시.
- [ ] 동일한 대표 인프라를 HCL·Plan·실제 AWS Inventory로 분석하고 의미상 비교 가능한 관계와 판정이 일치하거나 차이 사유가 설명됨.
- [ ] 동일 VPC, NAT, ALB/NLB→서비스, 서비스→DB, 다중 VPC, Endpoint, 정상/요청 차단/응답 차단/미확정 등 필수 시나리오의 기대 결과 검증.
- [ ] 실제 조회 권한이 있는 AWS 테스트 환경에서 읽기 전용 수집 및 결과 검증. 관측 증거와 정적 분석 차이 확인.
- [ ] 구조도 이동·접기·저장·복원·초기화, 정책 토글, 팝업 및 Packet Trace를 브라우저에서 통합 검수. 시각 변경 전후 분석 결과 동일.
- [ ] 업로드 실패·불완전 수집·동시 요청·타임아웃·재기동 및 구성 교체에 대한 오류 처리 검증.
- [ ] 전체 회귀 테스트 통과 및 브라우저 E2E, 실제 입력 통합 검증. 건너뛴 테스트 및 검증 한계를 명시하고 필수 검증을 미수행한 상태에서 출시 완료로 판정하지 않음.
- [ ] 대표 소규모/복합/대형 샘플의 성능 측정과 합의된 목표 충족. 목표 및 측정 환경을 별도 기록.
- [ ] 운영 형태에 맞는 보안 검수, 민감정보 유출 방지 및 읽기 전용 보장.
- [ ] 설치/운영/지원 범위/알려진 한계/검증 기록 문서화, Git 기준선 및 출시 버전 태그 지정.

1차 출시 운영 형태(로컬/사내/외부 공개), 대규모 성능 수치, 지원 서비스별 상세 기능, IAM·IPv6·다중 계정/Region의 정확한 지원 한계는 후속 설계에서 확정한다. 1차 출시를 특정 날짜까지 반드시 완료한다는 제한은 이 문서에서 신설하지 않는다.
